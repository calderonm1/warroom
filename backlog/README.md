# Backlog

The War Room backlog is **code**: YAML files in this folder, validated by a JSON Schema and synced one way to GitHub Projects for human viewing ([ADR-0014](../docs/adr/0014-backlog-as-code-github-projects.md)). The repo is the source of truth. Edits made on the GitHub board are overwritten.

## Layout

```text
backlog/
  README.md                 this file (format, rules, Definition of Ready and Done)
  milestones.yaml           M0..M7 capability gates (see docs/07-planning/roadmap.md)
  schema/backlog.schema.json
  epics/EP-NN-<slug>.yaml   one epic per file, containing its features and stories
  INDEX.md                  GENERATED by `make backlog-index`; never edit by hand
```

## Hierarchy and IDs

| Level | ID | Example | Notes |
| --- | --- | --- | --- |
| Epic | `EP-NN` | `EP-05` | A capability area; one file |
| Feature | `FE-NN.N` | `FE-05.1` | A coherent slice; prefix matches its epic |
| Story | `ST-NN.N.N` | `ST-05.1.2` | One PR's worth of work; prefix matches its feature |

IDs are **permanent**. Never renumber, never reuse. Cancelled stories stay with `status: cancelled`. New stories get the next free number in their feature.

## Story fields

```yaml
- id: ST-05.1.2
  title: Fixed64 type and math library
  type: feature            # feature | chore | spike | docs | infra | test | bug
  status: ready            # draft | ready | in-progress | blocked | done | cancelled
  priority: P0             # P0 blocks milestone .. P3 nice to have
  size: M                  # XS | S | M | L | XL (XL must be split)
  milestone: M1            # optional; inherits feature, then epic
  story: As a simulation developer, I want ..., so that ...
  acceptance_criteria:
    - Given ..., when ..., then ...
  docs: [docs/03-architecture/simulation.md#numbers]   # paths must exist
  refs: [SIM-020, ADR-0005]                            # IDs must be defined in docs/
  depends_on: [ST-05.1.1]                              # story IDs; no cycles
  labels: [sim]
  agent_notes: |           # optional; plans and decisions (CONV-AI-006)
```

Epic and feature status is **derived** from their stories (shown in `INDEX.md`): all done → done; any in progress → in progress; otherwise todo.

## Definition of Ready

A story may be `ready` only when:

1. The story statement names a role, a capability and a benefit.
2. Acceptance criteria are testable (prefer Given/When/Then).
3. `docs` links point to the governing doc sections, and `refs` cite the rule IDs it implements.
4. Size is XS, S or M (the validator rejects `ready` stories sized L or XL).
5. Dependencies are listed in `depends_on`.
6. UI stories define loading, empty and error states.

## Definition of Done

See [AGENTS.md](../AGENTS.md#definition-of-done-all-stories). In short: acceptance criteria demonstrably met with tests, `make check` green, docs updated in the same PR, story `status: done`, and `INDEX.md` regenerated.

## Commands

| Command | Purpose |
| --- | --- |
| `make backlog-validate` | Schema, unique IDs, ID prefixes, dependency integrity, no cycles, doc paths exist, refs defined |
| `make backlog-index` | Regenerate `INDEX.md` |
| `make backlog-next` | Stories that are `ready` and whose dependencies are all `done` |
| `make backlog-sync-plan` | Dry run of the GitHub Projects sync (prints planned changes) |
| `make backlog-sync` | Apply the sync (needs `GITHUB_TOKEN` with `project` and `repo` scope plus `WR_PROJECT_OWNER` and `WR_PROJECT_NUMBER`) |

## Detail levels

Epics for M0 and M1 are specified in detail (ready to work). Later epics hold coarser `draft` stories that are refined when their milestone becomes next. Refining means splitting, adding acceptance criteria and docs links, and moving to `ready`.
