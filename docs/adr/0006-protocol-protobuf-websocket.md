# ADR-0006: Protocol choices

- **Date:** 2026-10-18
- **Deciders:** project owner

## Context

Clients need a bidirectional, low-latency channel for commands and state updates that works on iOS, Android and browsers (BR-004), and simple request/response APIs for account, store, lobby lists and profiles. Contracts must be schema-first so agents can generate and verify code.

## Decision

1. **Real-time channel:** a single WebSocket (TLS) per client to the Gateway. Messages are **Protocol Buffers** (proto3) wrapped in a `ClientEnvelope` / `ServerEnvelope`. Schemas live in `shared/contracts/proto/warroom/<domain>/v1/` and are managed with **buf** (lint plus breaking-change detection).
2. **Meta API:** HTTP+JSON, described by **OpenAPI 3.1** at `shared/contracts/openapi/meta-api.v1.yaml`. The spec is the source of truth; server handlers are validated against it in CI (contract tests).
3. Versioning: protobuf packages carry a major version (`v1`). Breaking changes create `v2` alongside `v1` until clients migrate. The OpenAPI path prefix is `/v1/`.
4. Codegen for C# (client and server) is checked in under `Generated/` folders and marked read-only for agents; regenerated by `make contracts-gen`.

## Alternatives considered

| Option | Why not |
| --- | --- |
| gRPC / gRPC-Web | gRPC streaming is awkward in browsers and Unity WebGL; HTTP/2 proxies add complexity |
| JSON over WebSocket | Larger payloads, no schema enforcement, slower parsing on mobile |
| UDP / custom transport | Unnecessary for a strategy game with second-scale latency tolerance; blocked in browsers |
| MessagePack | Weaker cross-language schema tooling than protobuf + buf |

## Consequences

Browsers and Unity WebGL support WebSockets natively, so the web client needs no protocol changes. buf adds a tool dependency (pinned in `tools/`).

## Compliance

CI runs `buf lint` and `buf breaking --against main`. OpenAPI contract tests run in server integration tests.
